# AMK — Design & Code Audit

> **Scope note**: the AMK plugin source code is **not yet public**. This audit
> is based on the design description in `auto-annotated-portfolio`'s
> `amplenote-markdown-kanban.md`, the patterns observed in
> `Capta1nCool/an-kanban` (MIT, public), and the Amplenote SDK primer.
> This document is **architectural**: identify the slots, propose a
> reference implementation pattern, then surface the audit findings the
> future implementation must satisfy.

| Aspect | State |

## Design overview

| Concern | Approach |
| --- | --- |
| Where it runs | Amplenote **Sidebar embed** + a `noteOption`/`appOption` promoter |
| Data shape | `## Heading 1` → column; `- [ ] Task` → card; `- [x] Done` → completed; `<!--WIP:N-->` per-column; `<!--CARD:UUID-->` per-card |
| Round-trip | Whole-note overwrite via `app.replaceNoteContent({ uuid }, md)` — no block-level edit API guarantees |
| State | Pure derived state from note markdown; no ceiling-side caches |
| UI library | React 18 + `@dnd-kit/core` (already validated by `Capta1nCool/an-kanban`) |
| Markdown parsing | Hand-rolled line scanner — small enough that `mdast-util-from-markdown` adds bundle weight without much value |
| Persistence | Markdown is the source of truth; UI is a derived view |

### Data-shape design (justification)

```
## Backlog
<!--WIP:5-->
- [ ] Spec the kanban
- [x] Decide on input shape <!--CARD:c_8af-->
## In Progress
- [ ] Drag-and-drop cards
## Done
- [x] Initial design <!--CARD:c_95-->
```

- **Headings = columns.** Maps 1:1 to user mental model. Already supported
  by every note taking app; no learning curve.
- **Tasks = cards.** Native Amplenote Markdown tasks render in the note.
  No metadata collision.
- **`<!--CARD:…-->`** keeps a stable card ID even after reorder, so future
  per-card metadata (assignee, due date) can ride along in a future column
  without a migration.
- **`<!--WIP:N-->`** in column header enforces WIP visible to the user in
  the note — not just the embed — closing the "shadow UI" gap.
- **`[x]` checked tasks live in the same column as `[ ]`** rather than
  being moved to a "Done" column automatically. Auto-archive is a future
  opt-in setting; current portfolio description says "completed-column
  behavior" is a target feature, not yet shipped.

## Audit findings

### Strengths (per design)

1. **Markdown-as-DB is the lowest-friction persistence model in the
   Amplenote ecosystem.** No proprietary state, no export, no migration
   when the user reinstalls or shares the note.
2. **Heading-based columns are stable across reorderings.** Column IDs
   survive if a user renames a column heading (we keep the ID).
3. **WIP limits embedded in notes are a first-class user feature.** Most
   plugins hide state; this one benefits from being visible.

### Risks surfaced

1. **Whole-note overwrite via `app.replaceNoteContent` is lossy under
   concurrent edits.** Same as SRS.
   - Mitigation: parse incoming `markdown`, diff against current, only
     write if the diff is non-empty AND round-trip-stable
     (`parseBoard(serializeBoard(b)) === b` for safe shapes).

2. **Card IDs need a stable source of truth.** Random IDs in the parse path
   lose identity across re-orders. Always write back the same `<!--CARD:…-->`
   marker; only mint a new UUID for genuine new cards.

3. **`@dnd-kit` adds ~50–80 KB to the bundle.** Acceptable inside 220 KB
   soft, but if the embed HTML / CSS swells the size hits hard limit.
   - Mitigation: `npm run size-check` in CI; alert at 200 KB.

4. **Drag events inside the Amplenote sidebar are intermittent on
   touch devices.** `Capta1nCool/an-kanban` has this issue documented
   (their README flags "Column reorder md generation" and "Task
   completion" as ongoing). Treat touch support as out of scope for v1.

5. **Heading renames invalidate column IDs.** Re-deriving column IDs from
   the heading text means a user rename breaks drag targets.
   - Mitigation: when the user renames a column via the embed, write back
     the same column position with the new title (the entire board moves).
     The cost is one round-trip per rename.

6. **Markdown escaping inside backticks.** Amplenote's table escape bug
   (documented in SRS notes) applies here too — wrap user text in backticks
   before serializing when needed.

7. **Sandbox CSP issues.** `@dnd-kit`'s `DragOverlay` portal pattern can
   emit styles that assume a backdrop. Stay on the in-DOM droppable API;
   avoid `createPortal`.

8. **No tests for serialize/deserialize round-trip.** The most common
   failure class for "Markdown as DB" plugins is parser drift.
   - Mitigation: snapshot tests with both directions: `md → bd → md'` where
     `md' === md` for representative inputs, and `bd → md → bd'` for known
     stable boards.

### Lower-priority / nice-to-have

- `onEmbedCall` should support column reorder, WIP edit, done toggle, and
  raw markdown reload. Build the type as a union, not a string-typed
  handler, so future actions can't drift apart.
- Add an `app.settings` schema for default WIP, default sort, and
  "auto-archive done" feature flag before shipping.

## Reference implementation status

The `/home/frost/Amplenote-Markdown-Kanban/` scaffold contains the
essentials:

- `src/utils/md.ts` — typed `BoardModel`, `parseBoard`, `serializeBoard`
- `src/utils/board.ts` — pure `moveCard`, `toggleCardDone`, ...
- `src/utils/host.ts` — typed wrapper around `window.callAmplenotePlugin`
- `src/Board.tsx`, `src/components/Column.tsx`, `src/components/Card.tsx` —
  minimal React + `@dnd-kit/core` rendering
- `src/embed-entry.tsx` — single iframe mount + drag handler
- `vite.config.ts` — single IIFE bundle output, dependents external=
- `scripts/size-check.mjs` — soft/hard size limits
- `package.json` — typed dependencies, zero non-dev runtime imports declared

What is **not** yet written (gaps flagged for the next iteration):

- WIP-limit enforcement UI feedback
- Touch-input handling
- Block-precise mutation shim
- Vitest tests for `parseBoard` ∘ `serializeBoard` round-trip stability
- An actual `app.replaceNoteContent`-backed integration test (requires
  Amplenote host — defer)

## Risk score (informal)

| Area | Severity | Notes |
| --- | --- | --- |
| `replaceNoteContent` clobbers concurrent edits | High | Same family as SRS |
| Round-trip stability drift | High | Most likely v1 failure |
| Bundle size exceeding 220 KB | Medium | Alert path exists |
| Column rename → ID invalidation | Medium | One round-trip fix |
| Touch drag-and-drop unreliable | Low | Documented limitation |
| Markdown escape corruption | Low | Identical pattern to SRS |
